状态机与边界

文档状态queued → parsing → chunking → embedding → ready / failed
作业阶段parse → normalize → chunk → embedding → index
支持格式txt / md / html / htm / csv / pdf / docx / xlsx
明确不支持doc / xls、扫描件 OCR、多 embedding 维度混存
硬上限单文件 50 MB；单文档 5000 个 chunk
默认模型ollama / nomic-embed-text / 768

审查重点

  • workspace 隔离：所有查询和写入必须带 workspace_id，尤其检索、文档详情、source、重试和取消。
  • 上传安全：扩展名 / MIME / 大小 / 空文件 / 旧 Office 的稳定错误码是否覆盖完整。
  • 对象存储：路径穿越、重复 sha256、storage key 泄漏、失败回滚。
  • 幂等与并发：同一 sha256、同一 document 活动任务、重建与重试是否会重复写切片。
  • 向量一致性：768 维固定、维度校验、embedding model 记录、重建索引。
  • 检索正确性：topK clamp、阈值、hybrid 合并、citation 顺序、上下文截断。
  • 失败恢复：attempt / max_attempts、next_retry_at、heartbeat、lease、取消后不覆盖状态。
  • 预览安全：CSP、nosniff、Range、HTML 消毒、签名 URL 与对象存储 key 不外泄。
  • Agent 边界：Agent 只通过 runtime services 检索，不绕过仓库或直接拼 SQL。
最容易出错的四个位置
  • KnowledgeRepository.upload() 的对象存储与 DB 事务边界。
  • replaceDocumentChunks() 的原子替换与并发任务。
  • vectorSearch() 的 workspace、KB 和 embedding 过滤。
  • retrieveKnowledge() 的降级与 hybrid 合并分数。
